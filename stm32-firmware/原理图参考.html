2 · Proteus 器件库对照表

硬件清单里的器件Proteus 里搜什么说明
STM32F103C8T6 最小系统板STM32F103C8库里的元件名通常不带 T6 后缀。Blue Pill 成品板没有独立模型，直接用芯片本体；建议 Proteus 8.9 以上版本，对 STM32 支持更完整。
DHT11 温湿度传感器DHT11有模型 Proteus 8.6 以上自带。双击元件可以拖动滑条直接设温湿度值，很方便演示。
MQ-2 烟雾传感器POT-HG无模型 库里没有 MQ-2。标准做法是用可调电阻当分压源接 ADC，旋转旋钮模拟浓度变化。注意：仿真里不需要10k/20k 分压，但实物的原理图上必须画。
BH1750 光照模块POT-HG 或 POT无模型 同上，用可调电阻模拟光照输出电压，配合虚拟电压表观察 ADC 采样。
USB 转 TTL（CH340）COMPIM / VIRTUAL TERMINALCH340 芯片没有模型。要跟 PC 客户端真实通信就用 COMPIM（映射到虚拟串口对）；只想在仿真里看输出用 VIRTUAL TERMINAL，直接接 PA9/PA10。
ST-Link V2 下载器HEADER 4 / CONN-DIL4无模型 下载器不参与仿真，画一张 4 脚排针（SWDIO/SWCLK/GND/3.3V）表示接口即可。
电阻 10kΩ / 20kΩRES通用电阻，双击改阻值。Proteus 里也可以写 10k 直接识别。
5V / 3.3V / GNDPOWER / GROUND3.3V 网络默认名是 VCC 或 +3.3V，可在 Power Rail Configuration 里改名，保证与代码里的 3V3 定义一致。
虚拟示波/电压表（可选）DC VOLTMETER调试 ADC 通道时挂在 PA0 上看分压后的实际电压，很直观。

4 · MQ-2 分压电路（最容易出错的地方）

不接分压会烧 PA0

MQ-2 模块 5V 供电时 AO 输出最高可达 5V，而 STM32 的 ADC 输入上限是 3.3V。直接连上去会超过引脚绝对最大额定值，长期使用会损坏 ADC 通道。

接法：

MQ-2 AO ──[10kΩ]──┬── PA0 (ADC1_IN0)
                  │
                [20kΩ]
                  │
                 GND
  • 分压比 = 20 / (10 + 20) = 2/3，PA0 实际电压 ≈ 0.67 × AO
  • AO 满幅 5V 时 PA0 ≈ 3.33V，正好卡在 3.3V 上限，安全
  • 保守方案：换成 10k / 10k 分压（比例 1/2），代价是 ADC 量程只用一半
  • Proteus 仿真里不需要这两个电阻（用可调电阻直接给 ADC 供电），但实物的原理图必须画

5 · 在 Proteus 里搭图的检查清单

必做的设置

  • 双击 STM32 模型 → Program File 指向 Keil 编译出的 .hex（Keil 里要先勾上 Output → Create HEX File）
  • 同一对话框里把 Crystal Frequency 改成 8MHz，否则跑出来的数据会异常
  • 3.3V 网络名要和代码里的定义一致
  • DHT11 的 DATA 线在图上补一个 4.7k 上拉（Proteus 里给 DHT11 模型也要有）

容易踩的坑

  • Proteus 的 STM32 默认用内部 RC 振荡器，如果代码里切了外部晶振可能会直接卡住
  • DHT11 仿真模型的时序容差比实物宽，仿真跑通不代表实物没问题，实物上还要重点验证 DHT11 和 MQ-2 的采样时序
  • MQ-2 实物要预热 2~3 分钟，仿真里没有这个过程
  • Proteus 默认是实时仿真速度，DHT11 时序对 CPU 性能敏感，卡顿会导致读取失败

关于数值缩放（来自接线表）

温度/湿度是真实值 ×10（25.6℃ → 0x0100），但烟雾/光照按测试向量是原始整数不缩放（312 → 0x0138）。别统一乘 10，画图和联调时按这个对照检查报文。
