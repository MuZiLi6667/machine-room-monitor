# 接口规范（三端契约文档）v1.0

> **冻结日期：2026-09-21。本文档是三个模块之间唯一的接口依据。任何字段修改必须三端确认后升版本（v1.1、v1.2…），禁止单方面变更。**
> 各端实现细节（内部函数命名、UI布局、线程写法）可自由发挥，但**对外接口必须与本文档逐字节一致**。

---

## 1 全局约定

| 项 | 值 |
|---|---|
| 服务器监听端口 | **TCP 9000** |
| 串口参数 | **115200 波特率，8 数据位，无校验，1 停止位（115200-8-N-1）** |
| 传感器编号 sensor_id | 1=温度(℃)　2=湿度(%RH)　3=烟雾(ADC原始值 0~4095)　4=光照(lux) |
| 数值精度 | 温度/湿度保留1位小数；烟雾整数；光照整数 |
| 数据上报周期 | 单片机→客户端→服务器均为 **2 秒/次** |
| 心跳周期 | 客户端→服务器 **30 秒/次**；服务器 **90 秒** 无任何消息判定离线并断开 |
| 字节序 | 串口帧内多字节字段一律**大端（Big-Endian）**；网络层为JSON文本无字节序问题 |

## 2 串口帧协议（单片机 → 客户端）

### 2.1 帧格式（总长 = 4 + N + 1 字节，N=数据域长度）

```
┌────────┬────────┬────────┬────────────┬────────┐
│ 帧头    │ 帧类型  │ 数据长度 │ 数据域      │ 校验和  │
│ 2B     │ 1B     │ 1B     │ N B        │ 1B     │
│ 0xAA55 │ 0x01   │ N      │ 见2.2      │ SUM    │
└────────┴────────┴────────┴────────────┴────────┘
```

- **帧头**：`0xAA 0x55`
- **帧类型**：`0x01`=传感器数据帧（本期仅用此类型；预留 0x02 心跳、0x03 应答）
- **校验和 SUM**：从**帧类型字节**到**数据域最后一个字节**（含）逐字节累加，取**低 8 位**（mod 256）
- **粘包/错帧处理（客户端必须实现）**：在字节流中搜索帧头 → 校验长度（数据长度 ≤ 64 合法）→ 校验 SUM。任一步失败则丢弃到下一帧头位置重新同步，**不得因错误帧影响后续帧解析**

### 2.2 数据帧数据域（N = 1 + 3×n 字节）

```
传感器个数 n(1B) + n × ( 传感器编号(1B) + 数值(2B 大端有符号int16) )
```

数值 = 真实值 × 10 后取整。示例：25.6℃ → 256 → 0x0100。

### 2.3 标准测试向量（实现后必须 100% 通过）

**向量V1（全4传感器：25.6℃ / 55.0% / 烟雾312 / 光照356lux）**
```
AA 55 01 0D 04 01 01 00 02 02 26 03 01 38 04 01 64 E3    （共18字节）
```

**向量V2（仅温湿度：20.0℃ / 45.0%）**
```
AA 55 01 07 02 01 00 C8 02 01 C2 98    （共12字节）
```

**向量V3（负温度：-5.2℃ / 60.0%，验证int16有符号解码）**
```
AA 55 01 07 02 01 FF CC 02 02 58 32    （共12字节）
```

**异常向量（客户端解析器专项测试）**

| 用例 | 输入 | 预期 |
|---|---|---|
| E1 错校验 | V1 将末字节 E3 改为 E2 | 丢弃整帧，后续帧正常 |
| E2 粘包 | V1+V2 直接拼接 | 两帧均正确解析 |
| E3 半帧 | V1 前9字节，1秒后补齐余下 | 解析为一帧（缓冲不丢） |
| E4 噪声前缀 | `FF 12 00` + V1 | 跳过噪声后正常解析V1 |

## 3 TCP 应用层协议（客户端 ↔ 服务器）

**分帧规则**：每条JSON消息以 `\n` 结尾（UTF-8编码）。单条消息 ≤ 4KB。发送方保证JSON内无裸换行；接收方按 `\n` 切分缓冲区，不完整行留存等待。

### 3.1 消息定义

**客户端 → 服务器**

| type | 触发时机 | 格式 |
|---|---|---|
| `LOGIN` | TCP连接建立后**第一条**消息 | `{"type":"LOGIN","client_id":"PC-01"}\n` |
| `DATA` | 每收到一帧串口数据（2s周期） | `{"type":"DATA","ts":"2026-09-28 15:00:01","sensors":[{"id":1,"v":25.6},{"id":2,"v":55.0},{"id":3,"v":312},{"id":4,"v":356}]}\n` |
| `HEARTBEAT` | 每30秒（无DATA时） | `{"type":"HEARTBEAT"}\n` |

**服务器 → 客户端**

| type | 触发时机 | 格式 |
|---|---|---|
| `LOGIN_ACK` | 收到LOGIN后立即 | `{"type":"LOGIN_ACK","status":0}\n`（0=成功；同client_id重复登录：**踢旧连接、应答新连接** status=0） |
| `HEARTBEAT_ACK` | 收到HEARTBEAT后立即 | `{"type":"HEARTBEAT_ACK"}\n` |
| `ANALYSIS` | 分析线程每60s推送一次 | `{"type":"ANALYSIS","period_start":"2026-09-28 14:50:00","period_end":"2026-09-28 15:00:00","sensors":[{"id":1,"avg":24.1,"max":26.8,"min":22.3,"std":1.2,"over_count":3}]}\n` |
| `ALARM` | 任一DATA值超阈值时 | `{"type":"ALARM","level":"HIGH","sensor":1,"value":35.2,"threshold":30.0,"msg":"温度超上限","ts":"2026-09-28 15:00:01"}\n` |
| `ERROR` | 收到无法解析的消息 | `{"type":"ERROR","code":1,"msg":"malformed json"}\n` |

### 3.2 字段语义与容错

- `client_id`：1~31字符，`[A-Za-z0-9-_]`；默认取主机名，可在客户端界面修改
- `ts`：`"%Y-%m-%d %H:%M:%S"`格式，**可缺省**——缺省或非法时服务器用自身当前时间入库
- `sensors[].id`：整数1~4；`v`：数值（int或float均可），必须接受
- `level`：`LOW`（一级超标）/ `MID`（二级）/ `HIGH`（三级，严重）
- 服务器对未知 `type` 回 `ERROR`（code=2, msg="unknown type"），**不断开连接**
- 心跳超时（90s无LOGIN/DATA/HEARTBEAT）：服务器关闭连接、释放会话
- 客户端断线重连：退避 5s → 10s → 20s → 30s → 30s…，重连成功后重新发LOGIN

### 3.3 标准测试向量

```json
{"type":"LOGIN","client_id":"PC-01"}
{"type":"DATA","ts":"2026-09-28 15:00:01","sensors":[{"id":1,"v":25.6},{"id":2,"v":55.0},{"id":3,"v":312},{"id":4,"v":356}]}
{"type":"HEARTBEAT"}
```
服务器必须接受以上三条且：DATA 解析为 4 个传感器值；非法JSON如 `{bad` 回 ERROR code=1。

## 4 数据库规范（MySQL，服务器实现，客户端/单片机无需关心，联调用）

库名 `machine_room`，字符集 utf8mb4。完整建表语句见 `server-linux/sql/init.sql`，三张核心表：

```sql
CREATE TABLE sensor_data (        -- 原始数据：每传感器值一行
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  client_id VARCHAR(32) NOT NULL,
  sensor_type TINYINT NOT NULL,    -- 1温度 2湿度 3烟雾 4光照
  sensor_value DECIMAL(10,2) NOT NULL,
  collect_time DATETIME NOT NULL,
  KEY idx_time (collect_time)
);

CREATE TABLE analysis_result (    -- 分析结果：统计周期结束生成
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  client_id VARCHAR(32) NOT NULL,
  sensor_type TINYINT NOT NULL,
  period_start DATETIME NOT NULL, period_end DATETIME NOT NULL,
  avg_value DECIMAL(10,2), max_value DECIMAL(10,2),
  min_value DECIMAL(10,2), std_value DECIMAL(10,2),
  over_count INT DEFAULT 0,
  created_time DATETIME NOT NULL
);

CREATE TABLE alarm_log (          -- 告警日志：超阈值时写入
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  client_id VARCHAR(32) NOT NULL,
  sensor_type TINYINT NOT NULL,
  value DECIMAL(10,2), threshold DECIMAL(10,2),
  level VARCHAR(8),               -- LOW/MID/HIGH
  alarm_time DATETIME NOT NULL
);

CREATE TABLE threshold_cfg (      -- 阈值配置：服务器启动时加载到内存
  sensor_type TINYINT PRIMARY KEY,
  min_value DECIMAL(10,2), max_value DECIMAL(10,2), level VARCHAR(8)
);
-- 初始数据：温度 MIN-18/MAX-26/HIGH；湿度 MIN-40/MAX-60/MID；
--          烟雾 MIN-NULL/MAX-400/HIGH；光照不告警（不插行）
```

## 6 联调对齐点（最终集成检查清单）

1. 单片机发出的帧 == 接口规范V1/V2向量格式（A自测）
2. 客户端能解析V1/V2/V3+E1~E4全部用例（B自测）
3. 服务器能处理3.3节全部JSON并正确入库（C自测）
4. 全链路：模拟器→客户端→服务器，`sensor_data` 表2秒新增4行，客户端曲线滚动，超阈值时客户端弹告警
5. 三端时间戳一致（同一数据：单片机发送时刻 ≈ collect_time，误差 < 3s）
